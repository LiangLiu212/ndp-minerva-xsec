# Platform decisions

Platform-level choices with their evidence. Physics choices that belong to a measurement live in
the channel YAML with a `status`; entries here explain the `default` values and record engineering
decisions. Format: date | scope | decision | evidence / rationale | where.

2026-09-04 | architecture | The platform is a separate repository that *imports* the MINERvA exploration repo (benchmark engine, paper releases, selection constants) and never edits it | The exploration repo is an audited, manifest-backed record with its own operating rules; the platform is experiment-agnostic machinery that must not carry that repo's decisions into code | `ndp/compare/minerva_bridge.py`, `ndp.yaml`

2026-09-04 | data model | One columnar `TruthTable` (GeV, GeV², mm; jagged final state as CSR) is the contract between generators, channels, surrogates and comparisons | Keeps the core numpy-only; every generator/experiment needs one adapter, not one per stage | `ndp/events.py`

2026-09-04 | selection | The MINERvA CC-inclusive selection is a vectorised transcription of `tools/cc_inclusive_selector.py`, certified row-by-row (0 mismatches on the 6304-row data file and 20k MC rows, including the failing-cut label) and against the audited run's counts (844/835 data, 43643/43361/43266 MC, 43175/91/212 migration, 41948/41922 numerator, 65041/65003 denominator, all reproduced with `frame: detector`) | uproot bulk reads make the surrogate build a 30-second job; the per-entry tool stays the reference | `ndp/adapters/minerva_anatuple.py`, `tests/test_minerva_certification.py`

2026-09-04 | phase space (channel default) | Truth lepton kinematics are evaluated in the **NuMI beam frame** (rotation about x by MAT's `numi_beam_angle_rad = -0.05887`) for `minerva_me_cc_inclusive_ptpz` | On MC run 110040 the reco−true muon pT core width (1.4826·MAD) is 0.278 GeV with detector-frame truth and 0.061 GeV with beam-frame truth (wrong-sign rotation: 0.465 GeV); same-cell fraction of the 224-cell migration 0.098 → 0.396; median pT bias −54 MeV → +1.6 MeV. The reco `muon_thetaX/Y` branches are therefore beam-relative, as MAT's `GetThetalepTrue` convention implies. The audited runs 2026-06-09/-19 in the exploration repo used the detector frame ("small phase-space-edge caveat"); their migration and unfolded shapes carry this mismatch — **reported to the user, who owns that repo; not changed here.** `frame: detector` reproduces their numbers. The archived pure-Python reproduction (`archive/ndp-minerva-xsec/xsec/kinematics.py::true_theta_p`) already applied this RotateX beam rotation, corroborating the convention | `channels/minerva_me_cc_inclusive_ptpz.yaml`, `tests/test_minerva_certification.py::test_beam_frame_sharpens_resolution`

2026-09-04 | surrogate (binned) | `P[:, j] = M[:, j]/num[j]` (columns sum to ≤ 1) and selected events whose truth fails the phase space or the true grid are an additive, POT-scaled background together with non-signal events | With these definitions folding the training MC's own truth reproduces its selected in-grid counts exactly (43361.0, max cell deviation 0) — an exact closure the platform tests enforce. The alternative (renormalising columns to 1, migration from all selected signal) redistributes real losses and double-counts feed-in | `ndp/surrogate/binned.py`, `tests/test_surrogates.py`, `tests/test_minerva_certification.py`

2026-09-04 | surrogate (parametric) | Per-true-cell robust location/width (median, 1.4826·MAD) of reco−true pT and reco/true p∥, Gaussian core only | Mean/std are dominated by the 1/|q/p| tails (std of reco−true pT is 147 GeV on this MC); the core widths (0.27 GeV detector frame → 0.06 GeV beam frame for pT; 8% for p∥) are what a smearing model should carry. Tails are a documented limitation, to be addressed by a flow-type surrogate on the same interface | `ndp/surrogate/parametric.py`

2026-09-04 | phase space vs geometry | The fiducial-vertex requirement is applied only to samples that carry detector geometry (`meta.has_geometry`); point-target generator runs are taken as generated on the fiducial target whose mass is `n_nucleons` | A vertex cut on a sample with no vertices would remove everything (observed: 0 events in phase space on the first GENIE run) while it is not a kinematic restriction | `ndp/channels/registry.py`

2026-09-04 | flux | The published 2110.13372 supplemental Table I (νμ/m²/10⁵ POT/GeV, 0–100 GeV) drives GENIE and cross-checks Φ; Φ itself stays the published 6.32e-8 ν/cm²/POT the exploration repo adopted | Table integral 6.265e-8 (ratio 0.991), the shortfall being two-decimal truncation above ~50 GeV. The MAT flux files at hand are `MnvH1D` objects unreadable without MAT libraries on this node | `resources/flux/`, `ndp/theory/flux.py`

2026-09-04 | GENIE normalisation | σ_avg/nucleon = ∫Φ Σ_i (w_i/A_i) σ_i^{CC}(E) dE / ∫Φ dE from the spline XML, target-mix weights are mass fractions | GENIE's `GMCJDriver` treats `-t` weights as density-weighted path lengths and divides by A (so they are mass fractions), matching the `H2O = O16[0.8888],H1[0.1111]` convention; the resulting 4.49e-38 cm²/nucleon for CC νμ at ⟨E⟩≈6 GeV is the textbook magnitude | `ndp/theory/splines.py`, `ndp/theory/generator.py`

2026-09-04 | GENIE runs | Productions are cached by a fingerprint of the physics spec + flux source; logging verbosity (`--message-thresholds Messenger_laconic.xml`) is outside the fingerprint | The first production wrote 790 MB of stdout per 30k-event job; verbosity is not physics | `ndp/theory/generator.py`

2026-09-04 | comparisons | Report unfolded (paper covariance, and paper + model-stat) and folded (−2lnL and Pearson with MC-stat) side by side; never a combined verdict | The two modes answer different questions (published unfolded result vs detector-level counts); the exploration repo's benchmark contract makes the same choice | `ndp/compare/`, `ndp/compare/report.py`

2026-09-04 | environment | No package installation; the platform runs on the default pixi Python (3.10) with a pytest-free test runner; `pixi.toml` documents the intended environment | The exploration repo's rule (no environment changes without approval) is respected; the user decides when to `pixi install` | `pixi.toml`, `tests/run_tests.py`

2026-09-04 | legacy artifact surrogate | `surrogates/.../binned_from_run_2026-06-19` (rebuilt from the audited run's exported migration/efficiency, detector frame, migration over all selected signal) is kept as a re-indexing check and fallback only | It reproduces the run's 43175-pair migration bit for bit but is not closure-consistent under the platform's conventions | `ndp/surrogate/binned.py::from_run_artifacts`
